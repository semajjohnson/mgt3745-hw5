## Findings

**Passed:** A13 outright, and better than predicted — bolt not only avoided pre-populating labels but wrote a comment citing my acceptance row by number. A12's 30-character limit was enforced. A11 and A14's filter UI was correct, accessible, and is what I kept. No `innerHTML`, no `console.log`. It preserved my existing error handling and even my `?apiDown` test hook untouched.

**Failed, and fixed:**

1. **Labels went to `localStorage` instead of D1.** The primary finding. Fixed by adding a `labels` table to `schema.sql` and two endpoints to `worker.js`, with validation moved server-side where it cannot be bypassed.
2. **Labels keyed by lowercased track name.** Two different tracks sharing a title would have collided, and a label would have outlived the dismissal of its item. Fixed by keying to the entry row id.
3. **Vite project layout.** `index.html` pointed at `/src/app.js` and `/src/styles.css`, which do not exist in my flat repo. Fixed by taking only the markup I needed.
4. **Google Fonts from two external origins.** A direct violation of my own STYLE.md refusal. Fixed by not copying bolt's `<head>`.
5. **Nine unused dependencies and bolt's own meta tags.** Fixed by not copying `package.json` or the `<head>`.

**What I could not fully verify:** whether bolt's filter behavior is correct for labels containing characters my tests never tried — accented characters, emoji, or a label differing from another only by case. My tests use plain ASCII, and the server compares with `LOWER()`, whose behavior on non-ASCII in SQLite I have not checked. I logged it rather than claiming it works; the next step is a test with a non-ASCII label.

**What this says about my context files:** every failure above is something no file of mine forbade. bolt followed every rule that was written down, including the one I predicted it would break. The fix is not a better prompt but a STANDARDS.md that states prohibitions, which is the SKILLS.md entry for this week.
